# 装到 iPhone 并让它一直能用

> 结论先行：**iOS 27 上不存在「签一次永久有效」的签名**。能做到的是「装一次、之后基本不用管」，
> 代价是后台有个东西替你续签。本文给出三条路，以及各自能撑多久。

## 一、为什么「永久签名」不存在

iOS 上让 App 能运行的凭证由三把锁组成，任何一把到期，App 立刻闪退打不开：

| 锁 | 内容 | 免费 Apple ID | 付费开发者（$99/年） |
|---|---|---|---|
| 证书 | 谁签的 | **7 天** | 1 年 |
| 描述文件 | 允许在哪些设备运行 | 7 天 | 1 年 |
| 设备 UDID | 授权列表 | 你签名时连的那台 | 最多 100 台 |

真正能绕开这三把锁的只有 **TrollStore**——它利用 CoreTrust 漏洞，装完的 App 永不过期、不需要重签，
那才是字面意义上的「永久」。但它只支持：

- iOS 14.0 – 16.6.1
- iOS 16.7 RC（仅 20H18 这一个 build）
- iOS 17.0

**你的机器是 iOS 27.0.1，差 10 个大版本，这条路彻底堵死**，不用再试各种 TrollStore 教程，
那些教程的适用区间全部止步于 17.0。

剩下能做的，就是「让续签这件事自动发生」。

## 二、三条路对比

| | Sideloadly（推荐起点） | SideStore | 付费开发者账号 |

**建议**：先用 Sideloadly 走通，跑一周看续签是否稳；不稳再考虑花钱。别一上来就买账号——
买之前先确认「这个壳你确实天天用」。

## 三、Sideloadly 路线（已就绪）

### 前置条件（一次性）

1. **iPhone 开启开发者模式**
   设置 → 隐私与安全性 → 开发者模式 → 打开 → 重启 → 重启后输密码确认。
   iOS 16 起这是强制的，不开的话装完点不亮，只会闪一下图标。

2. **信任这台 Mac**
   数据线连上后，手机上会弹「要信任此电脑吗」→ 信任 → 输锁屏密码。

3. **确认 Mac 和 iPhone 在同一 Wi-Fi**
   自动续签走局域网，不在一个网里就只能靠插线。

### 安装

1. 打开 `/Applications/Sideloadly.app`（已装 v0.72，支持 iOS 7–27+）
2. 顶部 **iOS 设备** 一栏应自动列出你的 iPhone；如果为空，见「故障排查」
3. **Apple ID** 填你的普通 Apple ID 邮箱
4. 把 `dist/SoujuShell.ipa` 拖进 **IPA** 那一格
5. 点 **Start**，会要求输入 Apple ID 密码，然后是一个双重认证的 6 位验证码
6. 装完手机上会出现图标，但**第一次点开会提示「未受信任的开发者」**：
   设置 → 通用 → VPN 与设备管理 → 开发者 App → 点你的 Apple ID → 信任

密码只在你本机交给 Apple 的登录接口，Sideloadly 不会存到别处（它会存一份 session 用于续签，
在它的设置里可以清）。

### 让 7 天变成「不用管」

Sideloadly 设置里勾上 **Auto Refresh**（自动刷新）。

它的工作方式是：后台有个 daemon，在证书到期前几天，趁 iPhone 和 Mac 在同一个 Wi-Fi、
且 iPhone 处于充电/空闲状态时，自动重新签名并覆盖安装。

**必须满足**：Mac 处于开机且未睡眠状态、Sideloadly 在运行（或允许它在后台）、两者同 Wi-Fi。
只要其中一条不满足就会漏签，漏过 7 天 App 就打不开了。

### 七天到期了，怎么补救

**不要卸载 App，直接用 Sideloadly 再 Start 一遍。** 因为 Bundle ID 没变，是覆盖安装，
App 沙盒里的数据全部保留——站点登录态、播放进度、离线缓存都在 `WKWebView` 的 localStorage 里，
卸载重装就全没了。

## 四、真要「几乎不用管」，只有一条路

如果上面那套「Mac 得常开」对你不现实，比如笔记本经常合盖带走，那就只剩付费账号：

- $99/年，签出来的是 **Ad Hoc 分发**，有效期 1 年
- 一年到期前重签一次，同样覆盖安装、数据不丢
- 顺带解决 3 个 App 的限制
- 这仍然不是「永久」——**每年那一次重签躲不掉**，只是把频率从 7 天降到 365 天

在 iOS 27 上，「永久」这个词没有技术解。付费账号是把维护成本压到「一年一次」的合规上限。

## 五、故障排查

| 现象 | 原因与处理 |
|---|---|
| Sideloadly 里看不到设备 | 换根**能传数据**的线（很多充电线只有电没有数据）；换 USB 口直连、别用 hub；手机上重新点「信任」；Mac 上确认没有别的工具（如访达同步）占用设备 |
| 提示 `Maximum App ID limit reached` | 免费账号每 7 天只能创建 10 个 App ID，等到下周或换一个 Apple ID |
| 装完图标点开闪一下就没 | 没信任开发者证书（设置 → 通用 → VPN 与设备管理）；或没开开发者模式 |
| 提示 `The identity used to sign the executable is no longer valid` | 证书真过期了。检查 Mac 和 iPhone 的日期时间是否都设为自动；然后重新 Start 覆盖安装 |
| 自动续签一直没生效 | Mac 睡眠了 / 不在同一 Wi-Fi / Sideloadly 被退出了。三者缺一不可 |
| 安装时报 `Unable to install`，日志里有 profile 相关错误 | 免费账号的 profile 只含签名时连着的那台设备的 UDID，换设备要重新签 |

## 六、这个包为什么适合侧载

已核对 `dist/SoujuShell.ipa`：

- `MinimumOSVersion = 15.0`，iOS 27 可运行
- 架构 `arm64` 单架构，无 x86 冗余
- **无 `PlugIns`、无 `Frameworks`**——没有 App Extension、没有第三方动态库，
  免费账号签不了的那类东西它一个都没有
- 只依赖系统库（Foundation / AVFAudio / libobjc / libSystem）
- 当前是 `adhoc` 签名、`TeamIdentifier` 为空——这正是 Sideloadly 要覆盖的那一层，无需预先处理
- Bundle ID `com.wuxiaogang.soujushell`，与工程一致，覆盖安装能保留数据

## 七、和 Xcode 的关系（别走弯路）

这台 Mac 是 macOS 12.7.6 + Xcode 14.2，**Xcode 14.2 的真机调试只支持到 iOS 16.2**，
插上 iOS 27 的 iPhone 会直接报「device not supported」。

所以**不要试图用 Xcode ⌘R 装到这台手机**，装不上，跟工程配置无关，是工具链版本差太远。
Sideloadly 走的是自己的 USB 通信（libimobiledevice 系）和 Apple 的签名接口，不经过 Xcode，
这也是它能在 macOS 12 上装 iOS 27 的原因。
